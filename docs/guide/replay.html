Time-Travel Message Replay & Offset Rewind

Inspect historical event streams, replay from specific timestamps, and troubleshoot production incidents without broker restarts.

Standard live streaming displays events as they are produced in real time. EventOre’s time-travel replay engine allows operators and engineers to specify starting criteria (Earliest, Latest, Specific Offset, or ISO-8601 Timestamp) to scrub backwards in time and stream historical messages seamlessly into the live console.

Supported Replay Modes

  • Latest (Default): Tails incoming stream messages starting from the moment the subscription connects.
  • Earliest: Begins consuming from the oldest available message in broker log retention.
  • Timestamp Rewind: Seeks partition offsets to the earliest record whose produce timestamp is greater than or equal to the specified ISO-8601 datetime (e.g. 2026-10-05T14:30:00Z).
  • Explicit Offset / Shard Sequence: Targets a precise partition and offset number for surgical investigation of corrupted records.

Initiate Replay via WebSocket

Send a subscription frame over /ws/stream specifying the starting seek parameters:

// Connect WebSocket to /ws/stream
{
  "action": "SUBSCRIBE",
  "connectionId": "kafka-prod",
  "destination": "payments.captured",
  "startingPosition": "TIMESTAMP",
  "timestamp": "2026-10-05T14:00:00.000Z",
  "maxMessages": 500
}

The backend resolves the offsets using the provider inspector SPI, positions consumer poll iterators, and streams historical records before transitioning to active tailing.

Non-Destructive Historical Search

For immediate ad-hoc inspection without opening a persistent stream socket, query the inspector search API:

curl -X POST http://localhost:8080/api/v1/connections/kafka-prod/search \
  -H "Content-Type: application/json" \
  -d '{
    "destination": "orders",
    "partition": 0,
    "startOffset": 142000,
    "limit": 50,
    "filterRegex": ".*\"status\":\\s*\"FAILED\".*"
  }'
