Cross-Broker Replication & Bridging

Multi-source to multi-target streaming bridge engine with header mutation, regex filtering, loop prevention, and interactive dry-run testing.

Engine Capability (REQ-110): Eventore provides an active, asynchronous streaming bridge that transfers events across heterogeneous messaging clusters — such as Apache Kafka ↔ RabbitMQ, AWS Kinesis → GCP Pub/Sub, or local MQTT → Azure Service Bus — without external connector frameworks.

Overview & Architecture

In modern enterprise architectures, services often produce messages to distinct brokers: edge microservices might publish to lightweight RabbitMQ or MQTT, while analytics backends consume from high-throughput Apache Kafka or AWS Kinesis.

Eventore's ReplicationBridgeEngine runs concurrent, non-blocking worker pipelines using Java Virtual Threads and reactive streaming to consume from any configured source profile, apply transformation pipelines, and publish into target destinations.

Key Capabilities

  • Cross-Protocol Bridging: Bridge between any of the 8 supported protocols (Kafka, RabbitMQ, Pulsar, MQTT, JMS, AWS Kinesis, GCP Pub/Sub, Azure Service Bus).
  • Loop Prevention: Enforces X-Eventore-Bridge-Id and hop counter tracking headers to eliminate cyclic message loops in bidirectional or mesh topologies.
  • Payload Filtering: Evaluates incoming records against regular expressions or JSONPath predicates, safely dropping non-matching payloads before target transmission.
  • Header Transformation: Dynamically injects, removes, or mutates metadata headers (such as routing keys, correlation IDs, and environment markers).
  • Dry-Run Verification: Interactive simulator tests bridge filter predicates and header mutations on sample payloads without publishing to downstream brokers.
  • Real-time Telemetry: Real-time monitoring of replicated record counts, throughput (msg/s), byte volume, dropped records, and active worker statuses.

Creating a Replication Bridge via API

Bridges can be declared and started dynamically via the REST API:

curl -X POST http://localhost:8080/api/v1/bridges \
  -H "Content-Type: application/json" \
  -d '{
    "name": "kafka-to-rabbitmq-orders",
    "description": "Forward processed orders to warehouse queue",
    "sourceConnectionId": "conn-kafka-prod",
    "sourceTopic": "orders.v1",
    "targetConnectionId": "conn-rabbitmq-warehouse",
    "targetTopic": "warehouse.orders",
    "filterRegex": ".*\"status\"\\s*:\\s*\"CONFIRMED\".*",
    "headerTransforms": {
      "X-Forwarded-By": "Eventore-Bridge",
      "X-Environment": "production"
    },
    "batchSize": 100,
    "pollIntervalMs": 250,
    "loopPrevention": true
  }'

Interactive Dry-Run Testing

Before starting production replication, validate filter accuracy and header injection using the dry-run tester API: 

curl -X POST http://localhost:8080/api/v1/bridges/dry-run \
  -H "Content-Type: application/json" \
  -d '{
    "samplePayload": "{\"orderId\":\"ORD-9821\",\"status\":\"CONFIRMED\",\"total\":149.99}",
    "sampleHeaders": { "X-Tenant": "US-EAST" },
    "filterRegex": ".*\"status\"\\s*:\\s*\"CONFIRMED\".*",
    "headerTransforms": {
      "X-Bridge-Origin": "Kafka-Prod",
      "X-Tenant": "US-EAST"
    }
  }'

The response immediately reports whether the message was accepted, the transformed headers, and matching latency:

{
  "matched": true,
  "filtered": false,
  "transformedHeaders": {
    "X-Tenant": "US-EAST",
    "X-Bridge-Origin": "Kafka-Prod",
    "X-Eventore-Hop-Count": "1"
  },
  "executionDurationMs": 2
}

Lifecycle & High Availability

Bridges support START, PAUSE, and STOP lifecycle transitions. When running in a clustered Kubernetes deployment with PostgreSQL externalized connection stores, bridge states and metrics synchronize across pods to ensure seamless failover.
