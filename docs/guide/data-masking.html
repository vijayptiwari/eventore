Field-Level Data Masking & PII Redaction

Real-time recursive JSON and regex data masking to protect sensitive customer data, credentials, and PII across live streams and message inspection.

Privacy & Compliance (REQ-105): Eventore inspects and masks streaming payloads in memory before rendering in the browser UI, recording to audit logs, or streaming via WebSocket. This ensures complete GDPR, HIPAA, and PCI-DSS compliance.

How Data Masking Works

Eventore incorporates a dedicated, zero-copy DataMasker service powered by Jackson AST recursive tree walking. When messages arrive from any broker (Kafka, RabbitMQ, MQTT, etc.), the payload is evaluated against active masking rules:

  • Field Name Matches: Matches target JSON property names (e.g. password, ssn, creditCard, apiKey) case-insensitively across nested objects and arrays.
  • JSONPath Selectors: Pinpoints deeply nested paths such as $.customer.payment.card_number or $.billing.accounts[*].secret.
  • Regex Value Scanners: Scans string values and plain-text payloads for patterns such as credit card numbers (Luhn-compliant), email addresses, Social Security Numbers, and JWT tokens.

Masking Strategies

Eventore supports three configurable transformation strategies:

Strategy Sample Input Masked Output Description
REDACT "secretToken": "xyz-12345" "secretToken": "******" Replaces the entire value with a fixed-length mask.
PARTIAL "cardNumber": "4111222233334444" "cardNumber": "4111********4444" Preserves leading and trailing characters for debugging while concealing the middle.
HASH_SHA256 "userId": "user_9841" "userId": "a7b3c8...e1" Produces a deterministic salted SHA-256 hash to allow tracking events across partitions without revealing the identifier.

Configuring Masking Rules

Rules can be specified globally in application.yml or configured per connection profile:

eventore:
  masking:
    enabled: true
    default-strategy: REDACT
    rules:
      - name: "Credit Card Redaction"
        strategy: PARTIAL
        preserve-prefix: 4
        preserve-suffix: 4
        pattern: "^(?:4[0-9]{12}(?:[0-9]{3})?|5[1-5][0-9]{14}|3[47][0-9]{13})$"
      - name: "Credential Fields"
        strategy: REDACT
        fields:
          - "password"
          - "apiKey"
          - "client_secret"
          - "token"
          - "authorization"
      - name: "Social Security Numbers"
        strategy: REDACT
        pattern: "^\\d{3}-\\d{2}-\\d{4}$"

Live Streaming & Inspection Safety

When operators view live messages in the Live Streaming Workspace or execute point-in-time topic inspection, the data plane applies masking before transmitting frames over WebSocket. Operators without elevated security permissions never receive raw unmasked secrets on their client workstations.
