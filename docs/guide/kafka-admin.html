Kafka admin

Topic lifecycle, ACLs, produce with headers, and cluster operations — ADMIN mode with Kafka registered.

Kafka admin requires deployment-mode: ADMIN, Kafka on the classpath, and protocol registered in the control plane (adminProtocols includes KAFKA).

Topic management

  • Create topics with partition count and replication factor
  • Alter configuration (retention, compression, …)
  • Delete topics (with confirmation in UI)
POST /api/v1/connections/{id}/kafka/topics
{
  "name": "orders.events",
  "partitions": 6,
  "replicationFactor": 3
}

Produce with headers

POST /api/v1/connections/{id}/kafka/topics/{topic}/produce
{
  "key": "order-42",
  "value": "{\"status\":\"created\"}",
  "headers": {
    "content-type": "application/json",
    "trace-id": "abc-123"
  }
}

ACLs

View and manage Kafka ACLs when the cluster supports ACL APIs and credentials have sufficient privileges.

GET  /api/v1/connections/{id}/kafka/acls
POST /api/v1/connections/{id}/kafka/acls

Consumer group operations

  • List groups and members
  • Inspect lag per partition
  • Reset offsets (where permitted) — use with care in production

OpenAPI

Kafka-specific operations are defined in openapi/streams/kafka-api.yaml and exposed in Swagger when the Kafka provider is active:

http://localhost:8080/openapi/streams/kafka-api.yaml
