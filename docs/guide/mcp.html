MCP server for AI agents

Optional Model Context Protocol layer that exposes Eventore control and data plane APIs to Cursor, Claude, and other MCP clients.

Role in the architecture

Eventore separates control plane (provider registration, UI cascade, no broker TCP) from data plane (connections, publish, subscribe, inspect). The MCP server is a thin agent adapter — it never embeds Kafka or MQTT clients. All broker I/O goes through the same backend delegates as the React UI.

AI client ── MCP (stdio or HTTP) ──► eventore-mcp ── REST/SSE ──► Eventore backend
                                              │
                    control plane ◄───────────┼───────────► data plane
                    /api/v1/control           │           /api/v1/connections
                                              ▼
                                         Brokers / cloud streams

See also Control & data plane and Architecture.

When to deploy MCP: Use it when agents need to probe brokers, publish test messages, or inspect Kafka lag without the web UI. Skip it if operators only use the console — fewer pods and less attack surface.

Recommended agent workflow

  1. Read eventore://config or call eventore_get_config — deployment mode and controlPlane.uiCascade.
  2. Read eventore://control-plane or eventore_get_control_plane — confirm the target protocol is in activeProtocols.
  3. Use prompt eventore_discover for a full onboarding brief, or eventore_protocol_guide for broker URL hints.
  4. Data plane: eventore_create_connection → validate → list destinations → publish/consume/inspect.
  5. Admins only: control-plane eventore_register_provider / eventore_deregister_provider (requires ADMIN mode and ADMIN_BROKER_OPS).

MCP prompts

Prompts return ready-to-run playbooks for agents:

  • eventore_discover — loads config + control plane + architecture map
  • eventore_probe_broker — ephemeral probe via eventore_quick_probe
  • eventore_kafka_inspection — cluster → groups → lag → search sequence
  • eventore_control_plane_ops — register / deregister / status checklist

Cursor configuration (stdio)

cd mcp/eventore-mcp && npm install && npm run build

Add to Cursor MCP settings (see mcp/eventore-mcp/cursor-mcp.json.example):

{
  "mcpServers": {
    "eventore": {
      "command": "node",
      "args": ["C:/path/to/eventore/mcp/eventore-mcp/dist/index.js"],
      "env": {
        "EVENTORE_API_URL": "http://localhost:8080/api/v1",
        "MCP_TRANSPORT": "stdio"
      }
    }
  }
}

Docker & Helm (published artifacts)

CI publishes ghcr.io/vijayptiwari/eventore-mcp and chart oci://ghcr.io/vijayptiwari/charts/eventore-mcp. Full image/chart list: Published Docker images & Helm charts.

# Stack: backend + frontend + MCP
docker compose -f docker/docker-compose.stack.yml up -d

# Published MCP image only (backend elsewhere)
docker pull ghcr.io/vijayptiwari/eventore-mcp:latest
docker run -p 3100:3100 -e MCP_TRANSPORT=http \
  -e EVENTORE_API_URL=http://host.docker.internal:8080/api/v1 \
  ghcr.io/vijayptiwari/eventore-mcp:latest
helm install eventore oci://ghcr.io/vijayptiwari/charts/eventore --version 0.1.0 \
  -f deploy/helm/eventore/values-published.yaml

helm install eventore-mcp oci://ghcr.io/vijayptiwari/charts/eventore-mcp --version 0.1.0 \
  --set eventore.apiUrl=http://eventore-backend:8080/api/v1

HTTP health: GET :3100/health. MCP endpoint: POST/GET :3100/mcp (streamable HTTP).

Policy and security

  • Deployment mode on the backend applies to MCP the same as the UI — READONLY blocks publish and connection CRUD.
  • MCP_AUTH_TOKEN protects the MCP HTTP endpoint only; configure Spring Security separately if the backend API must be authenticated.
  • MCP pods do not need broker network access if the backend already reaches brokers.

Limitations

  • Live streaming in the UI uses WebSocket /ws/stream; MCP consume tools use SSE for bounded samples.
  • Cloud protocols (Kinesis, GCP Pub/Sub, Azure Service Bus) are supported when the provider JAR is deployed and registered; inspect/admin tools vary by provider.
  • MCP does not replace the web console for multi-topic live view or export.
