About Eventore

Eventore is an open-source, multi-protocol messaging console. It gives operators and engineers one place to connect, browse, live-stream, inspect, and administer Kafka, Pulsar, RabbitMQ, MQTT, JMS, AWS Kinesis, Google Cloud Pub/Sub, and Azure Service Bus — with slim deployments that include only the protocols you need.

The product is built around a modular control plane and data plane: stream providers register at runtime, and the UI reflects what your cluster actually exposes. That design supports local debugging, shared workspaces, and production Kubernetes installs with Helm and GHCR images.

How to contribute

How to report issues, propose changes, and land pull requests that match the project structure.

Thank you for helping improve Eventore. Set up the local stack in the product guide, then follow the workflow below.

Ways to contribute

  • Bug reports — reproducible steps, logs, and protocol or cloud preset used
  • Documentation — docs/ product guides and diagrams (run SEO inject before PR)
  • UI — React components and live-stream workspace in frontend/
  • API & providers — Spring modules under eventore-provider-*
  • Helm & CI — deploy/helm/, Dockerfiles, GitHub Actions workflows
  • MCP tools — mcp/eventore-mcp for agent integrations

Before you open a PR

  1. Fork github.com/vijayptiwari/eventore and create a branch from main.
  2. Set up the local stack and confirm your change against at least one broker (Docker Compose brokers are enough for most work).
  3. Run relevant checks:
    • Backend: mvn -DskipTests package (or full tests if you touched core logic)
    • Frontend: npm run build in frontend/
    • Docs: node docs/scripts/inject-seo.mjs when you change HTML under docs/
  4. Keep changes focused — one feature or fix per pull request when possible.

Pull request guidelines

  • Describe what changed and why in the PR description.
  • Note which protocols or deployment modes you tested (e.g. Kafka + ADMIN, READONLY smoke test).
  • Include screenshots for UI changes and sample API requests for backend behavior.
  • Update user-facing docs in docs/guide/ when behavior or configuration changes.
  • Do not commit secrets, connection strings, or real cluster credentials.

Adding a stream provider

To add or extend a protocol integration:

  1. Create eventore-provider-<id>/ with connector and inspector packages implementing StreamProvider.
  2. Register *StreamProviderAutoConfiguration in META-INF/spring/...AutoConfiguration.imports.
  3. Add the module to eventore-server/pom.xml and a Maven profile if it should be optional.
  4. Extend ProtocolType in eventore-core and the OpenAPI contract under openapi/.
  5. Regenerate API sources and implement delegates in eventore-server.
  6. Add a product guide page docs/guide/<protocol>.html, sidebar entry in docs/js/site.js, and an entry in docs/seo/pages.json.
  7. Document GHCR image tag in deploy/ci-backend-images.json if CI should publish a slim image.

See backend/README.md § “Adding a new stream provider” for module-level detail.

Documentation contributions

  • Product copy lives in docs/guide/*.html — match existing tone and section structure.
  • About and contributor pages live at docs/about.html (not in the product guide sidebar).
  • Regenerate SEO blocks and sitemap: node docs/scripts/inject-seo.mjs.

Community standards

Be respectful and constructive in issues and reviews. Security-sensitive findings should be reported privately to the maintainers when possible rather than in a public issue with exploit details.
